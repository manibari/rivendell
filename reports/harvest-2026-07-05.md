## Skill 候選

### 🟢 Strong — `llm-batch-scoring`（headless LLM 批次評分/分析管線）

- **Purpose**：固化「role-prompt LLM 分析師 + 結構化輸出契約 + 批次落庫」的建置模式：(a) prompt 契約設計 — 角色定義、輸入資料打包（清單/取樣）、**單一 JSON 物件輸出、明令禁 markdown 圍籬與解說**、schema 欄位與值域（如 sentiment -1~1）；(b) 逐實體批次迴圈（每股票/每專案一次呼叫）；(c) 輸出驗證與失敗重試/降級；(d) 結果落庫（mart 表或 markdown 報告）。
- **Trigger**：「用 LLM 批次評分」「LLM 情緒/訊號分析」「建 LLM 分析 agent」「LLM-as-judge 管線」「把 LLM 輸出寫進 DB」。
- **Category**：`backend`
- **Rationale**：**同一模式跨 2 專案出現 4+ 次**——mops-dbs 的新聞情緒評分（session 1–3，並在 session 4 以 `0003_llm_signals.py` 落庫）與 rivendell 的 token 用量日報分析師（session 6，commit 46cb94e）形狀完全相同：餵資料 + 角色 prompt → 結構化輸出 → 排程持久化。現有 skill 均不覆蓋這層：`headless-agent` 管 runner/排程/日誌基礎設施（互補，不重疊）；`doc-to-structured-data` 是文件抽取；`ai-vision-extract` 是視覺。缺的正是 **prompt 輸出契約 + 批次評分管線**這層 how-to。
- **建議**：以 `skill-creator` 抽取，內容從 mops-dbs `0003_llm_signals.py` + rivendell token-analysis agent 兩個實例交集提煉（符合 [[fleet-infra-spine]] 的「從成熟實例交集抽取」原則）。
