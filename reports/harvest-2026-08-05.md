## 二、Skill 候選

### 🟢 Strong — `skill-apply`（匯入外部 skill 就地套用評估）

- **目的**：把已匯入本機的外部 skill repo（尤其是審查/評估/稽核類，如 grill-me、domain-modeling、tdd、diagnose 這類「拷問/檢查清單」型 skill）套用到**當前專案的具體 target**（單一專案架構、或多個 target 如板子/模組清單），逐一跑過套用邏輯，產出結構化 findings（每個 target 一份判定文件）+ 優先順序行動清單。把「匯入外部 skill」到「拿它評自己」這一步的斷點接起來。
- **觸發**：「這個 skill 拿來評我的專案」「用剛匯入的 skill 看一下 X」「基於 [外部 skill 名] 檢查 [target 清單] 有沒有偷吃步/符合規範」，或匯入完成後緊接著的評估請求。
- **類別**：meta（`skill-*` prefix series，與 `skill-scout`、`skill-creator` 同層，銜接而非取代）
- **理由（本輪核心發現）**：這是 `harvest-2026-08-03.md` 標記的 🟡 Moderate 候選（`skill-import-and-apply`，190 msgs，Session 6：匯入 `matt-skills` → 套用評估 ChimesFlow 架構）**在兩天後的第二次發生**——今天 Session 4（683 msgs，本輪最大量）是同一支 `matt-skills`，換一個專案（PTI-ARES）、換一種套用方式（5 個 target 逐一過 domain-modeling/tdd/diagnose 檢查清單，而非單一架構總覽）。08-03 報告當時的結論明講「若再發生一次同型任務，再決定是否獨立成 skill」——現在證據量已滿足：
  - 兩個不同專案（ChimesFlow、PTI-ARES）各發生一次，皆非同一次 session 的延續

- **設計提醒（來自 Session 4 的觀察）**：
  1. 683 msgs 且被使用者中途打斷兩次——單一 session 一次跑 5 個 target × 4 個檢查維度顆粒度太粗，容易失控。skill 應該支援「一個 target 一輪、可中斷續跑」，而非一次全跑完。
