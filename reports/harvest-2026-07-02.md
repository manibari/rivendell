## Skill 候選

### 🟡 Moderate — `double-entry-ledger`（自建複式簿記會計引擎 domain reference）
- **Purpose**: 承載複式簿記的正確性不變量與落地骨架——借貸必平、分錄不可變更（append-only）、交易事件自動生分錄、科目表(CoA)/總帳/試算表/財報、庫存估值(FIFO/加權平均)——並提供「進銷存交易事件 → 借(Dr)/貸(Cr) 分錄對映表」。同 `odb-dfm-reference` 的定位：穩定、教科書級、跨產品的**領域參考**，非 code 抽象。
- **Trigger**: 「複式記帳 / double-entry / 會計引擎 / 分錄 / 總帳 / 試算表 / 進銷存帳務 / ERP 記帳」；為 FastAPI+Postgres 產品加入交易→自動分錄時。
- **Category**: backend
- **Rationale**: erp-scope.md 已把會計核心明確定位為 **domain-agnostic、營建請款(第二垂直)後補**，且 Norns-ERP requirement 對 M5 會計引擎「寫到最深、用大量測試守正確性」——這正是值得固化的穩定知識。**但真實實作仍 n=1**（tukey-bi 只做到進銷存的「會計稽核」，非完整分錄引擎）。使用者自己的紀律是「**第二實例才驗證抽象**」（[[fleet-infra-spine]]、erp-scope「不提早抽象」），故此刻評 Moderate 而非 Strong：**先觀察，待營建請款或第二個記帳產品出現、對映表被複用一次，再升格抽 skill**。屆時應是 reference 型（知識），不是 scaffold 型（code）。

### 🟡 Moderate — `retail-replenishment-dashboard`（門市補貨→稽核→一鍵出貨單看板）
- **Purpose**: 固化零售/經銷的補貨看板 recipe：POS 串接庫存/銷量 → 需求預測（README 稱 **forecast-as-measure，把模型預測當一等公民 measure**）→ 勾選品項**一鍵生成出貨單** → 總部會計稽核 → 出貨看板；並帶「role as a lens」（門市/會計/admin 同資料不同視角）與標準 ERP 模組式 IA（進銷存/主檔/報表/系統）。
- **Trigger**: 「門市補貨 / POS 看板 / 需求預測 / 一鍵出貨單 / 經銷出貨稽核 / 零售補貨儀表板」。
- **Category**: workflow（或 frontend）
- **Rationale**: 在 tukey-bi(240 msgs, 本批最大 session) 有完整實作（BchShell.tsx 的角色分流 nav、forecast-as-measure、role-as-lens 已落地），且 Norns-ERP 明確要**沿用**這段當進銷存楔子——即將被複用。但目前仍是**同一血脈 n=1**（bch → Norns 是延續，非兩個獨立產品各自實作）。依「第二實例才驗證抽象」紀律，先評 Moderate/觀察；Norns-ERP 若在**非金軒揚客戶**上重跑此補貨模式，即為第二實例證據 → 升格。
