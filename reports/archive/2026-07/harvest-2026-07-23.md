## Skill 候選

### 🟡 Moderate: worktree-lane-handoff

- **用途**：多 worktree 常駐「車道」架構（如 main/engine/ui/art，各對應一個 persona）下，session 啟動時的例行檢查——依 invocation 標籤認領自己的車道 → 掃描 `main`（或其他車道）worktree 有沒有屬於自己車道的未 commit 改動（依 AGENTS.md 的檔案/目錄所有權規則判斷）→ 用 patch 方式搬到正確的 worktree + branch → 用 `git diff` byte-exact 驗證搬移前後內容一致。
- **觸發時機**：session 以特定 lane persona 身分啟動（如「你這邊是負責 X 介面」），且專案的 AGENTS.md 定義了多 worktree 分工規則。
- **涵蓋步驟**：認領車道 → 掃描外部 worktree 的漏放 WIP → 產生 patch → 套用到自己車道 → diff 驗證兩邊一致 → 回報現況（哪些 worktree 停在哪個 baseline）。
- **分類建議**：`git`（與 `concurrent-session-git` 同層，互補而非重疊）。
- **來源**：MingOS-ui session 完整示範了這個流程，且不是臨場發明——明顯是照專案既有 AGENTS.md 規則走。
- **現有相似**：`concurrent-session-git` 處理的是**同一個** working tree 被兩個 session 同時撞到之後的回復；`dispatching-parallel-agents` 的 worktree 是**臨時**指派給平行任務、用完即棄。這個候選是**常駐**多 worktree 架構下的**啟動例行檢查**，三者可以並存、各自涵蓋不同時機。
- **建議**：目前只在 MingOS 一個專案觀察到，且依賴該專案已有的 AGENTS.md 慣例。先記錄，若未來在其他採用類似「多 worktree 常駐分工」的專案（如有多產品線用相同模式）再次出現，就用 skill-creator 建立。
