## Skill 候選

### Moderate — `demo-anonymize`（presales 資產去識別化）

| 欄位 | 內容 |
|------|------|
| **Name** | `demo-anonymize`（暫名；或 `presales-sanitize`） |
| **Purpose** | 把真實客戶交付資產（dashboard HTML、截圖、CSV/資料、簡報）洗成可對其他 prospect 重用的「示範客戶」版本：(a) 客戶名/品牌/負責人 → 佔位字（示範客戶 / DEMO Co.）；(b) 真實數字 → 保留量級的擬真假資料；(c) 截圖敏感欄位遮罩（圈選 + 模糊/色塊）；(d) 檔名與檔內字串一致替換 + 自我截圖檢查確認無殘留真實資訊 |
| **Trigger** | 「做 demo 版」「去識別化」「洗成示範客戶」「mask 截圖」「這個 case 之後要給別的客戶看」 |
| **Category** | `docs`（presales 資產處理；與 `sales-material` / `pitch-deck` 同層） |
| **Rationale** | 多步驟、領域特定、現有 skill 群有明確缺口，且服務反覆出現的 presales 痛點。可沿用 CLAUDE.md「生成圖後一律自我截圖檢查」原則的延伸（這裡是檢查「有沒有殘留真實客戶資訊」）。**唯一保留意見：本批僅 n=1**。建議：若 user 確認此流程會反覆（presales 重用 demo 是常態，大機率會），可直接抽；否則記入 learnings，待第 2 次出現再促進。 |

## 建議行動

1. **詢問 user**：presales demo 去識別化是否為反覆流程？是 → 用 `skill-creator` 抽 `demo-anonymize`（含「洗完自我截圖檢查殘留」hard gate）；否 → 走步驟 2。
2. **記 learnings（platform-meta vault：`rivendell/.learnings/` 或 presales 相關）**：去識別化 checklist 雛形
   - 客戶名/品牌/人名 → 佔位（全域字串替換 + 檔名同步）
   - 真實數字 → 保留量級的假資料（量級對才有說服力）
   - 截圖遮罩後**自我截圖 Read 檢查無殘留**（沿用 CLAUDE.md 截圖驗證原則）
   - 交付前 grep 真實客戶名/統編確認 0 命中
   → 待第 2 次出現即促進為 skill。
