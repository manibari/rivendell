## Skill 候選

### 🟡 Moderate — `seed-deployed-app`（本地資料 → 已部署 App 灌入）

| 欄位 | 內容 |
|------|------|
| **Purpose** | 當一個 App 已經部署上線（有 auth、有正式 DB），要把本地開發/舊系統的既有資料安全地灌入正式環境：登入取得 token → 比對本地 schema 與線上 API → 逐批 POST/PUT 推送 → 驗證筆數一致。 |
| **Trigger** | 「把本地資料移到線上」「seed 正式站」「資料搬到部署好的站台」「migrate data to deployed app」「線上是空的，幫我把資料灌進去」 |
| **Category** | `backend` |
| **Rationale** | Session 1 花了 202 則訊息、Bash 91 次處理這件事，且觸及 `auth.py` / `auth-context.tsx` / `api.ts` / `ci-cd.yml`——典型「對著一個活著的、需要登入的正式環境推資料」的流程，與現有 skill **不重疊**：`db-migration` 是 schema migration 工具、`sqlite-to-postgres` 是換 DB 引擎、`deploy` 是部署設定，**沒有一個處理「資料 payload 透過認證 API 灌入線上 App」**。可 codify 的固定步驟：①取得登入憑證/token ②抓本地資料來源 ③對齊線上 API 欄位（環境差異）④分批推送 + 速率/錯誤處理 ⑤線上線下筆數驗證 ⑥避免重複灌（去重/idempotent）。 |
| **Recurrence 風險** | ⚠️ 目前僅 **1 次** 出現（單一專案）。建議**先記為候選、暫不建 skill**，待下一個專案再出現「灌正式站」需求（≥2 次）時即抽出。此處先把固定步驟記下，降低下次的探索成本。 |
