## Skill 候選

### 🟢 Strong — `deck-anonymizer`（簡報/文件去識別化）

- **Name**: `deck-anonymizer`（暫名，亦可 `presales-anonymize`）
- **Purpose**: 把一份含真實客戶身分的 presales/pitch deck（HTML 或 PPTX 來源）轉成**去識別化的可重用版本** —— 替換公司名、移除 logo、模糊化財務/痛點/客戶 issue 等敏感欄位，輸出 sanitized `index.html` 並逐頁截圖自我驗證沒有殘留可識別資訊。
- **Trigger**: 「去識別化」「匿名化這份簡報」「拿掉客戶名字」「sanitize this deck」「做成 sample/案例版」「anonymize client」。
- **Category**: `docs/`（與 `pitch-deck` / `sales-material` / `slide-workflow` 同域，作為下游清洗步驟）。
- **Rationale**:
  - Session [1] 完整走了一條多步流程：來源 deck → `index.html` → 透過 `AskUserQuestion` 確認去識別化範圍 → 逐頁產 `anon-s01-cover.png`…`anon-s14-appx-client-issues.png` 截圖檢查。`anon-` 前綴 + 附錄 `client-issues` 被特別處理，顯示這是「把真實案子洗成可對外展示的參考案例」的明確需求。
  - 與 user 的 B2B presales 主線高度吻合（CLAUDE.md 的 Slide / 客戶情蒐流程、`presales-pipeline`、`sales-material` 都在做客製 deck）——做完一個客戶後想重用成 sample，去識別化是反覆會踩到的步驟。
  - 現有 skills **沒有任何**去識別化/匿名/redact 能力（已 grep `skills/` 與 `~/.claude/skills/` 確認）。`protect-secrets` 只處理 code/env secret，非簡報內容客戶身分。
  - 有明確驗證 pattern 可 codify：符合 CLAUDE.md「生成圖後一律自我截圖檢查」原則 —— 去識別化後必須截圖逐頁確認無殘留（logo 顏色、頁尾來源、appendix 真名）。
  - **建議內容**：(1) 敏感欄位 checklist（公司名/統編/人名/logo/財務數字/特定痛點/頁尾來源標記）；(2) 一致性替換（同一假名貫穿全 deck，避免 s03 叫 A 公司、s14 又露真名）；(3) 截圖驗證 gate。
