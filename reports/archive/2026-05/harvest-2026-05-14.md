## Skill 候選

### 1. code-playbook-extractor — **Moderate**

- **Purpose**：當專案有 N 份做類似事情的程式碼（多支 scraper、多支 API client、多支 form handler）散落在不同模組時，掃描所有實作 → 萃取共通模式 → 分階段組織 → 產出 `docs/<DOMAIN>.md` 作為專案官方方法論文件（含分階段、共通 helper、anti-pattern）。
- **Trigger**：「整理我目前的 X 方法與手法」「幫我把 X 寫成 playbook」「produce official `<domain>.md`」「現有程式碼太散，要統一」
- **Category**：`workflow/`
- **Rationale**：
  - Session #5 是本批最大會話（152 msgs、$0 cost），Bash:Edit:Write = 85:17:9 顯示「大量掃 code → 中量寫 markdown → 少量 helper 抽出」的典型 archaeology pattern。
  - 檔案產出（`SCRAPING.md` + `collection-module-extraction.md` + `_http.py` + `db_skip.py`）反映出「主文件 + 萃取備註 + 共用 helper」的標準產出結構，可 codify。
  - **與既有 skills 區隔**：
    - `sync-readme` 是 README 層級不是方法論層級
    - `init-project` 是新專案初始化不是既有 code archaeology
    - `large-file-refactor` 改 code，不寫文件
    - `skill-creator` 寫 skill 不寫專案內部 playbook
  - **可重用場景**：scraping playbook（本次）→ testing playbook → API client playbook → form handling playbook → migration playbook。
  - **降為 Weak 的風險**：目前只有 1 個 session 範例。建議追蹤 1–2 次 harvest，若再看到類似模式（「整理我目前的 Y 方法」）即升為 Strong 並建立。
