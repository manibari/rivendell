## 技能候選

### Moderate — `tech-handoff-report`

- **目的**:當使用者判斷「README 不夠」,需要一份給接手者看的說明文件(現況+架構),生成後放在 repo 根目錄顯眼位置,涵蓋「我們目前幹什麼」「架構長怎樣」兩個核心問題。
- **Trigger**:「技轉報告」「交接文件」「讓人接手」「現況+架構說明」等使用者在 README 之外額外要一份說明文件的情境。
- **Category**: docs
- **理由**:Session 4 明確出現「還是你覺得 readme 就可以了 → 我還是需要先有一個大的說明」的判斷分岔,顯示這是一個獨立於 README 的文件類型(受眾是「要接手的人」,不是「要跑起來的開發者」)。已檢查 `client-kickoff-docs`(新客戶 kickoff scaffold,方向相反——專案剛開始 vs 專案要交接)與 `sow-writer`(合約導向)皆不覆蓋此情境。但只有單一 session 出現,樣本數偏薄,建議先觀察是否再出現再拍板成獨立 skill。

### Weak — 其餘模式皆有既有 skill 或屬一次性任務,不建議新建

- **Session 2(顧問導入一頁簡報+Excel+送 Downloads 可調整版)**:內容產出已由 `office-pptx` / `office-xlsx` / `sow-writer` 覆蓋;「生成後另存可調整版送 Downloads」是這些既有 skill 的輸出習慣,不是獨立技能。
- **Session 3(git 分支是否已 push + 補功能)**:單次的「查狀態→補功能」序列,屬於一般開發任務範疇,沒有可抽象的固定步驟,且與 `gstack-review` / `gstack-land-and-deploy` 已覆蓋的「diff review→部署驗證」流程重疊。
