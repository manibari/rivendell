## Skill 候選評估

### 🟢 Strong：`bash-strict-mode-audit`（shell 嚴格模式靜默早死稽核）

- **Purpose**：掃出 `set -euo pipefail` 腳本中會**靜默提前結束**的語意陷阱，並產出修法。核心是那些「語法正確、shellcheck 也不會抱怨、但在 strict mode 下會殺掉整支腳本」的寫法：命令替換裡的 `grep`/`head` 在無匹配時回 1、`((i++))` 在 i=0 時回 1、`local x=$(...)` 吞掉 exit code、`touch`/`mv` 對不存在的路徑、`read` 在 while 末行回 1、`set -e` 在 function 與 `if` 條件內失效。輸出：檔案:行號 + 分級（已實爆 / 可觸發 / 理論）+ 每項的修法。
- **Trigger**：
  - 「腳本跑到一半就停了」「沒有錯誤訊息但沒做完」「exit 0 但事情沒做完」
  - 排程 agent 失敗但 log 是空的
  - 新增或修改 `bin/` 下的 shell 腳本之前的 pre-flight
  - `set -e`、`pipefail`、`shellcheck 過了但還是壞`
- **Category**：`quality/`
- **Rationale**：
  - **n≥3 且每一次都真的爆過，全部有紀錄可查**：
    - `bin/sk-reports-janitor:45` — `file_date=$(echo "$base" | grep -oE '...' | head -1)`，遇到 `workflow-retro-2026-W18.md` 這種沒有 `YYYY-MM-DD` 的檔名時 grep 回 1 → pipefail → set -e 直接殺掉。**08-02 03:00 搬到一半就死**：檔案已刪、`janitor.log` 因為死在寫檔之前完全沒產生，那批檔案移動**到現在（08-04）還卡在 `git status` 未提交**。第 48–58 行專門處理 ISO-week 的分支是死碼，永遠到不了。此 bug 是 W31 retro 的 Action 1，**兩天後仍未修**。
    - `bin/sk` 曾有 33 處 `((count++))`（2026-07-17 修）— counter 從 0 開始時回傳舊值 0、`(( ))` 求值為零即 exit 1 → `sk deploy` 連結完第一個 skill 就死，**而且印出綠色成功訊息**。後果是 `~/.claude/skills/` 裡絕大多數 symlink 長期指向已搬走的舊路徑。這不是遷移漏步驟，是 macOS 上一樣會爆的真 bug。
    - `bin/sk-watchdog` 的 `touch .next/.build-complete` — 建置失敗時 `.next` 不存在，touch 在 set -e 下會殺掉 watchdog；2026-07-27 加 `[ -d .next ]` 才擋住。
  - **現況有 12 個未防護的 `$( ... grep ... )` 分佈在 6 支腳本，全部在 `set -euo pipefail` 下**：`sk-reports-janitor:45,49`、`sk-ssot-drift-cron:28`、`sk-disk-monitor-cron:32,34`、`sk-agent-doctor:164,173`、`sk:272,283,287,1277`。這些不是理論風險——janitor 那兩行已經證明了觸發條件有多平凡（一個檔名不合格式）。
  - **正確寫法已經存在於同一個 repo**：`bin/sk-harvest-cron:59` 用了 `|| echo "0"`。**知識有，執行機制沒有**——這正是 skill 該補的位置，和 `portability-sweep` 的論證形狀完全一致（CLAUDE.md 有手寫規則但無稽核）。
  - **既有 skill 不覆蓋**：`env-doctor` 是 runtime 環境探測（版本/依賴/連線），不讀 shell 語意；`github-repo-audit` 看結構/文件/CI 健康度；`protect-secrets` 只掃密鑰；`qa-*` 是應用層測試。且 **shellcheck 本身抓不到這兩類最貴的**（`((i++))` 的 exit code、pipefail 早死都不在其預設規則內），所以「跑 shellcheck 就好」不是替代方案。
  - 這類 bug 的特徵是**偵測成本遠高於預防成本**：每一次都表現為「靜默 exit、無 log、印綠字」，事後要靠 `bash -x` 重跑才定位得到（session 6 就是這樣做的）。
- **建議結構**：
  - `SKILL.md`：陷阱分類 → 掃描 → 分級 → 修法套用
  - `scripts/strict-audit.sh`：分類 grep + 三級輸出，明確標註「shellcheck 不會抓這些」
  - `references/exit-code-traps.md`：每個陷阱的最小重現（`bash -c 'set -euo pipefail; x=$(echo a | grep b); echo reached'`）與修法（`|| true` / `|| echo default` / `count=$((count+1))` / 先宣告再賦值）
  - `references/where-set-e-doesnt-apply.md`：function 內、`if`/`&&`/`||` 條件、subshell 的差異
