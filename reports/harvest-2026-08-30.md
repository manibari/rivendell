1. **[1]–[3] dispatch 具體化引擎**（3 個 sessions，各 1 則訊息）：headless 執行「把模糊指令變成結構化提案 JSON」的 prompt。範例輸入：約光泉窗口開會、記錄「rivendell 不掛 codex oauth」的決策。純 JSON 輸出，不動任何工具 — 執行交給 `scripts/dispatch-lib.py` 狀態機。
2. **[4]–[5] 實體知識庫維護**（2 個 sessions）：從最近 sessions 的使用者訊息摘要中萃取持久事實，經 `scripts/kg.py` 寫入知識庫。即 `sk-facts-cron` 每日 21:30 的排程工作。
3. **[6] kuangchuan-bi 會前簡報**（21 則訊息）：唯讀讀取 `manibari/kuangchuan-bi` 專案，整理會前素材 — 看板功能清單、銷售預測模型現況、auto-deploy poller 狀態、技術債與改版方向。工具序列為 Glob → Grep → Read → Bash 的典型 repo 偵察流程。
4. **[7] rivendell 資料流圖**（169 則訊息）：先問「有畫資料流的 skills 嗎」，接著透過 `mermaid-diagram` skill 畫 rivendell 資料流圖，過程中大量編輯 CHANGELOG.md、README.md、ROADMAP.md、CLAUDE.md、MEMORY.md，並用 5 次 Agent fan-out。

### 觀察到的重複模式

- **模糊指令 → 結構化 JSON 提案**（sessions 1–3）：同一 prompt 骨架重複 3 次，已由 `sk dispatch` 確定性管線承載。
- **Session 摘要 → 知識庫事實**（sessions 4–5）：已由 knowledge-graph skill + sk-facts-cron 承載。
- **唯讀 repo 偵察 → 會前簡報素材**（session 6）:目前沒有 skill 承載，屬手工流程。
- **畫圖 → 連帶大量文件同步**（session 7）:mermaid-diagram 本體有 skill，但單次圖表工作外溢成 33 次 Edit 的文件同步，顯示 doc-drift-sync 的觸發時機可再前移。

## Skill 候選

### 1. repo-premeeting-brief — **Moderate**

- **目的**：唯讀掃描指定專案 repo，輸出結構化「會前簡報素材」：功能/頁面清單、模型或服務現況、排程/poller 運作狀態、已知技術債與改版建議，落地到 `materials/` 下的 markdown。
- **觸發**：「會前簡報」「整理 XX 專案現況」「幫我看一下 repo 準備開會」，且對象是**自己有 code 的內部專案**。
- **分類**:workflow
- **理由**：session 6 是完整、乾淨的一次示範（Glob → Grep → Read → 產出 markdown），與現有 skill 都不重疊 — `customer-intel` 做的是外部公司網路情蒐，`github-repo-audit` 做的是品質評分而非會議敘事。降為 Moderate 是因為目前只出現一次；若下次再出現同型需求，建議即刻用 `skill-creator` 立案。

### 2. dispatch-proposal-persona — **Weak**

- **目的**：把 sessions 1–3 的「具體化引擎」prompt 收編為 `agent-persona` 管理的版本化模板，而非散落在 dispatch 呼叫端。
- **觸發**：修改 dispatch 提案格式、新增提案類型時。
- **分類**:meta
- **理由**：模式確實重複（3 次），但執行面已被 `sk dispatch` + `dispatch-lib.py` 狀態機完整承載，缺的只是 prompt 的版本管理。屬於對現有 `agent-persona` 的套用，不需要新 skill；列出僅供 dispatch 維護時參考。

### 3. dataflow-inventory — **Weak（不建議建立）**

- **目的**：為專案自動盤點資料流（來源 → 處理 → 落地）並產生 mermaid 圖。
- **理由**：session 7 的實質工作已由 `mermaid-diagram` 覆蓋（該 skill 明確主張「ARGUE not DISPLAY」），盤點步驟屬一次性偵察。真正的訊號反而是：**圖表工作結束後的文件同步應交給 `doc-drift-sync`**，而不是在同一 session 手工編輯五份文件 — 這是既有 skill 的路由問題，不是缺 skill。
