§3

模組職責邊界

「不負責」那欄是這節的全部價值——它是日後爭議「這段邏輯該放哪」的唯一裁判。

模組負責不負責
sk-agent-run啟動一次執行、設定環境不記錄結果（那是 sk-exec-lib）
sk-exec-lib把一次執行寫成 agent_runs 一列不判斷成功的語意（只存 exit_code）；不寫 reports/
sk-registry-genregistry → agents.conf 格式不安裝 plist；不判斷 drift
sk-setup-agentsregistry → launchd plist不產生 registry；不執行 agent
lib/db.pyagent_runs 的連線與查詢不碰 token 三表
lib/tokens.py由 JSONL 算 token、快取、寫三表不讀 agent_runs
lib/roles.py角色 × PDCA 彙總不寫任何表（唯讀旁掛）
api/server.py39 個端點、序列化不含業務邏輯；不寫 DB
sk check對帳：宣稱 vs 實際不修復（只報告 + exit code）
sk-watchdog服務存活重啟不管內容是否新鮮（R3 的缺口）

邊界爭議的裁判：sk-exec-lib 不負責判斷語意—— 這就是為什麼 today_cost 顯示 0.0 卻不算說謊（cost_usd 確實沒人寫）。 要改的是新增一個寫入端，不是讓讀取端去猜。
