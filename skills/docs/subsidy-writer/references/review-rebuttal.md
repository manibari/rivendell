# 書面審查意見 → 審查會議簡報

送件之後的下一站。委員的書面意見表回來了，你要在審查會議上逐條回應。

Distilled from one real run (2026-08 數產署 AI 創新服務研發補助, 10 條委員意見, 60 頁送審計畫書,
官方 25 頁 .odp 範本 → 31 頁簡報 + 修正版計畫書, 六小時). 每一節都對應那次真的踩過的東西。

## 定調：這不是把計畫書再講一次

那次的規劃文件開頭寫著一句話，是整場的樞紐：

> 這場簡報不是把計畫書再講一次，而是**當場交出一份修正後的計畫書**。

10 條意見裡有 4 條在指同一件事——送審版的正文與表格對不起來。這種意見沒有「回答」的空間，只有
「修正」。所以這個階段的交付物是**兩份**：簡報，以及一份改過的計畫書 docx。只做簡報，等於在會議上
承認錯誤卻交不出改正。

## 第一步：把意見分成四類（分類決定回應形式）

先讀完整份意見表，逐條歸類。類別直接決定這條意見要花多少版面、以及要不要動計畫書本體：

| 類 | 性質 | 回應形式 |
|---|---|---|
| **A** | 文件內部不一致 | **必須提修正版，不能口頭辯護**。同時動簡報與計畫書 docx |
| **B** | 要補實質內容 | 每條開一頁新的證據頁 |
| **C** | 商業補強（常帶肯定語氣） | 併進既有章節加強，通常不另開頁 |
| **D** | 純肯定 | 意見回覆總表寫一行承接即可，**不另開頁** |

A 類是最容易誤判的。委員說「進度表與正文研發項目不一致，建議重新編列」時，那不是建議，是抓到錯。
那次的 A 類實況是：進度表寫 A35/B30/C35，**D 分項（20%）整個不見**，C 從正文的 15% 變 35%，
9 個查核點全是 A/B/C 沒有半個 D。這種東西上台辯護只會更難看。

每條意見在規劃表裡都要有四欄，缺一不可：

| 欄 | 為什麼不能省 |
|---|---|
| 委員意見 | 原文，不要改寫。委員會照自己寫的字追問 |
| **送審版實況（證據）** | 去送審 PDF 裡把對應段落挖出來、標頁碼。**沒有這欄就會憑印象承認或否認錯誤** |
| 回覆方向 | 具體到可以寫成投影片的程度 |
| 新增頁 | 空白代表這條不佔版面 |

「送審版實況」那一欄是這整張表的重心。那次靠它才發現委員 #7 說的「資安章節誤植」其實出在
「公司概況（四）產品銷售方式」——寫成了另一個案子的石化設備經銷通路。委員指錯了章節，但錯誤是真的。

### 主動更正

盤點過程會找到委員**沒抓到**的錯。那次額外找到人員簡歷 22 人全標「待聘」、計畫主持人在摘要表與
主持人資歷寫成兩個不同的人。

要不要主動更正是使用者的決定，不是你的——列成清單問，別自己挑。但值得講清楚利害：一張「主動更正
對照表」（錯在哪／改成什麼／對應頁）讀起來是嚴謹，被委員當場抓到第二次才是失分。

## 第二步：頁次規劃（官方大綱不可動）

官方 .odp 範本的章節大綱是硬約束，跟 Phase 1 的 目錄先行 同一條規矩。深答頁**塞進第一章之內**，
不要為了回應意見去改動或新增章。

那次的骨架，可直接沿用：

```
1     封面（勾選申請類別）
2     簡報大綱（照官方範本）
3     委員書面意見回復總表 ← 10 條 × 一句話回覆 × 頁碼
4     主動更正對照表        ← 委員沒抓到但你要改的
5-8   深答頁               ← 一條 B 類意見一頁
9+    官方 12 章正常內容，其中被意見打到的頁面加粗標記回應了第幾條
末    簡報結束
```

**第 3 頁是整份簡報的索引**：每條意見一句話回覆加頁碼。委員手上拿著自己寫的 10 條意見，這頁讓他
一眼確認每條都有著落。沒有這頁，委員得自己在 31 頁裡找答案。

## 第三步：逐頁素材盤點（寫內容之前）

這是那次最省時間的一步，也是最容易跳過的一步。**在寫任何內容之前**，逐頁標一次料況：

| 狀態 | 意思 | 後果 |
|---|---|---|
| ✅ | 送審版有現成內容可直接壓縮上台 | 照抄壓縮 |
| 🟡 | 有素材但要重寫／重算 | 排工 |
| 🔴 | 硬缺料，需外部資料或使用者決定 | **擋著，進拍板清單** |

每頁都要寫來源與頁碼（送審 PDF 第幾頁、哪個 cache 資料夾），🔴 的要寫清楚缺什麼。

那次 33 頁裡有 6 頁是 🔴，而且都是委員問得最兇的那幾條：

- 指標正名 Precision/Recall — 送審版只有「檢出 83 筆 vs 商用工具 76 筆」，**算不出 Precision
  （83 筆裡誤報幾筆？）與 Recall（ground truth 總違規數？）**
- 試點場域 — 候選池、篩選條件、標準樣本板組成表全缺
- 範疇優先序 — 「核心高頻規則」是 59 條裡的哪幾條，全新

沒有這張表，這 6 頁會在寫到第 20 頁時才發現寫不下去。有這張表，它們在第一小時就變成問使用者的
題目。

## 第四步：拍板清單（擋著開工的才進來）

跟 Phase 3 的 逐題拍板 同一個做法：一次問完，不要一題一題滴。但這裡多一層——**只有真的擋著開工的
才列**。那次只有四題：

1. 主動更正要改哪幾處（列出候選，讓使用者勾）
2. 經費要照送審版還是提修正版（那次送審版 100% 人事費，但正文承諾推廣與試點差旅，這組不一致無解）
3. 委員直接問的事實現況（試點名單到哪一步、意向書用印狀態）
4. **誰上台**——影響第一人稱口吻與講者備註的寫法

第 4 題看起來像小事，但它決定整份稿子的人稱。寫完 40K 字才問，等於重寫。

## 第五步：素材露出的敏感決策

審查簡報會被委員、承辦、可能還有其他廠商看到。動手放素材前先確認三件事，別自己決定：

- **客戶／廠商截圖能不能露出**——對方願不願意在政府簡報裡具名。不確定就匿名成產業描述（「某 PCB
  廠」），或直接把畫面裡的識別資訊塗掉。
- **人名的揭露範圍**——計畫主持人與關鍵人員通常必須具名（官方欄位要求），但其他人不必。
- **既有系統的實作截圖**——確認畫面上沒有客戶圖號、料號、廠別代碼。

這條與 `[[deck-case-anonymization]]` 一致：身分匿名成產業描述，技術數字留到最具體。

## 第六步：產出

順序與檔名沿用 Phase 4/7 的慣例，全部落在 `cache/YYYYMMDD-審查簡報/`：

```
簡報規劃_vN.md      ← 意見分類表 + 頁次規劃 + 拍板清單
逐頁素材盤點_vN.md   ← ✅🟡🔴 + 來源頁碼
簡報內容稿_vN.md     ← 內容 SoT，逐頁全文；使用者過一輪再往下
figures/            ← 被 A 類意見打到的圖要重出（那次圖 3 補回 D 分項、圖 4 對齊修正後進度表）
審查簡報_vN.pptx     ← 套官方 .odp 骨架
計畫書_修正.docx     ← A 類意見的修正版
```

`references/writing-rules.md` 的 Step 0 HARD GATE 在這個階段照樣適用，而且更嚴——回應委員的文字
是直接對著審查委員說話的，內部策略詞（佐證／命門／加分／紅線）洩漏出去比在計畫書裡更糟。收尾一樣
跑 de-slopify 的 審查文體掃描。

圖檔規格照 `references/figures.md`：這是**簡報**不是文件插圖，回到 1600×900，跟 Phase 7 的
1600×620–740 文件插圖規格不同——同一批圖要重出，不要縮放。

## 收尾檢查

- 每條委員意見在第 3 頁的總表都有一句話回覆與頁碼，一條不漏
- 每條 A 類意見在計畫書 docx 裡真的改了，不只在簡報上說會改
- 被重編的數字（權重、查核點數量、經費）在**簡報、修正版計畫書、圖檔**三處一致——這是 Phase 6
  連動網 check 的同一條規矩，只是現在跨了三種檔案
