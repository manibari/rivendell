# Task Brief — 任務定義教練

> 來源：改編自 [`skill-lab`](https://github.com/Jacktsai2785/skill-lab)（Jack Tsai）的
> `task-brief`。在 rivendell 歸入 `meta/`，定位為 **Step 0 任務定義 / 路由 gate**
> （獨立第二意見：Codex 2026-06-16）。框架整理自 YouTube「你不是不會寫 Prompt，
> 是不會定義任務」。

把「模糊的交辦」翻譯成「AI 能正確執行的任務定義」。這是一個管理 / 溝通動作，不是 prompt 技巧。

**開場宣告：** 「我用 task-brief 先把這個任務定義清楚，再決定怎麼交給 AI。」

## 核心原則（為什麼要先做這一步）

現在的模型是 senior 等級的協作者：它收到指令就直接動手，**不會回頭問你「這任務你現在想清楚了嗎？」也不會告訴你「你還在思考階段、不該叫我出完整成品」**。它預設 helpful，所以你留的每一個空白，它都會自己用「通用、平均、看起來完整但沒有觀點」的內容填掉。

所以兩件事永遠是你的責任，AI 不會替你補：

1. **判斷任務現在在哪個階段** —— 不同階段該餵 AI 的東西完全不同（Step 1）。
2. **把想清楚的任務翻譯成對方能接的形式** —— 到執行階段就是五欄位 brief（Step 2）。

> 好的 AI 使用者跟一般人的差距，不在 prompt 寫得多漂亮，而在交辦前會停一下、想清楚這任務該怎麼交。

## 與其他 skill 的關係（路由，不重複）

task-brief 是 gate，不是 peer。判斷階段後**路由到對的下游 skill，自己不重做它們的事**：

| 情境 | 路由到 | task-brief 不做 |
|---|---|---|
| 思考 / 探索有產品模糊、要逼問 | `gstack-office-hours` | 不自己跑完整蘇格拉底批判 |
| 要 user story / 驗收標準 | `requirement` | 不自己寫完整需求文件 |
| 複雜實作要追蹤式計畫檔 | `planning-with-files` | 不自己建 task_plan |
| 具體執行任務、要交 handoff | 產出五欄 brief（Step 2） | — |

---

## Step 1 — 判斷階段（四階段路由器）

**先問自己也問使用者：這個任務現在是要 AI「陪我想」、「列選項」、「評估我的決策」，還是「直接產出」？**

用 `AskUserQuestion` 讓使用者選一個階段（除非從上下文已經很明確）。每個階段的正確餵法：

| 階段 | 你現在的狀態 | 該叫 AI 做什麼 | 千萬不要 |
|---|---|---|---|
| **思考** | 問題本身還沒想清 | **反問你**、幫你把模糊變具體 | 叫它出完整成品（它只能給沒觀點的通用版）|
| **探索** | 問題清楚，要看選項 | map options、列 trade-off | 叫它直接推薦（你還沒有判準）|
| **決定** | 選項已知，要選一個 | 拿**你的**判準去評估、評分 | 叫它重新探索、給它沒判準的「你覺得呢」|
| **執行** | 方向已定，要產出 | 照五欄位 brief 做事 | 跳過 brief 直接丟一個「動作」 |

路由：

- **思考** → 反問模式：丟 5–8 個鋒利問題逼出具體（對象是誰？要解什麼？成功長怎樣？最小切入點？）。一次問一輪、等答完再往下。產出是一句被磨利的問題陳述 / thesis。產品級模糊可改路由到 `gstack-office-hours`。
- **探索** → 選項模式：列 2–4 個方向，每個附 trade-off，**不下推薦**。產出選項對照表。
- **決定** → 評估模式：先請使用者給**他的判準與決策邏輯**，AI 拿這組判準評分每個選項、給傾向 + 理由，**不重新發散**。
- **執行** → 進入 Step 2。

> 判斷錯階段 = 餵錯東西 = 產出一定偏。在思考階段就叫 AI 出 draft，是最常見的浪費。

詳細判準與各階段失敗模式見 `references/stage-router.md`。

## Step 2 — 五欄位 Brief（只在執行階段）

逐欄訪談：**AI 問、使用者答**。不要替使用者自己填——他沒講清楚的地方你一填就變 generic。

### 1. 目標（Goal）
- **問**：這份產出做出來，是要支持你做什麼**決定**或行動？
- **坑**：大多數人寫「動作」（幫我做競品分析），不是「決定」（這分析要支持下季產品方向）。寫成決定，AI 才知道往哪聚焦。

### 2. 背景（Context）
- **問**：一個今天才空降、但很聰明的同事，需要先知道哪些才不會抓錯方向？
- **坑**：你腦中的前提（公司規模、客群、踩過的雷）AI 不知道。

### 3. 素材（Materials）
- **問**：可以用哪些來源（主要 / 次要）？哪些**不准**用？
- **坑**：AI 預設「沒禁止的都能用」，找不到還會編。必寫反捏造條款：「找不到就說找不到，不要編。」

### 4. 邊界（Boundaries）——最多人漏的一欄
- **問**：有什麼是**不要碰、不要假設、不要編**的？
- **坑**：只給方向＝開放式 brief，自由發揮空間最大。邊界是那道牆。

### 5. 完成定義（Definition of Done）
- **問**：什麼產出結構、到什麼程度才算完成？
- **做法**：要求**先給 outline / 框架，審過再展開**——便宜階段攔下方向錯誤。
- **坑**：完成定義是 what（你定），不是 how（每步怎麼做，AI 自己定）。規定 how 就是微管理。

### 組裝
五欄填好組成**可直接貼上的 markdown brief**，結尾注入：

> 「對任何不確定的事，先反問我再動手，不要自作主張。」

逐欄定義、輸出範本、好 / 壞對照範例見 `references/five-fields.md`。

## Step 3 — 稽核模式（使用者已有一份 prompt / brief）

使用者貼來一段 prompt 問「這樣夠嗎 / 還缺什麼」：

1. 對照五欄位，逐欄標記 **有 / 弱 / 缺**。
2. **特別抓「素材」與「邊界」**——最常整個消失，也是 AI 最易自由發揮 / 捏造的破口。
3. 缺漏**以「問題」丟回給使用者**，不要自己幫他填。
4. 補完後走 Step 2 組裝。

---

## Step 4 — 交棒

brief 完成後它就是要交出去的 prompt：開新執行 agent / session 貼進去、接給既有執行型 skill、或換人 / 外包做都通用。
